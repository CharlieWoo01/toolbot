# Lock file

`tools/<name>/tool.lock.json` is generated by `toolbot update` and `toolbot check`. Don't edit it by hand.

```json
{
  "lockfileVersion": 1,
  "tool": "pact-broker-cli",
  "version": "0.8.6",
  "tag": "v0.8.6",
  "source": {
    "provider": "github",
    "repository": "pact-foundation/pact-broker-cli",
    "host": "https://github.com"
  },
  "assets": {
    "windows-amd64": {
      "upstream": "pact-broker-cli-x86_64-pc-windows-msvc.zip",
      "destination": "tools/pact-broker-cli/pact-broker-cli-x86_64-pc-windows-msvc.zip",
      "size": 3174680,
      "sha256": "bb639caabdcfde754c4059b99f181efa9f64a5a87699bf185c8a75b7c7e8dc40",
      "verifiedBy": "sha256:pact-broker-cli-x86_64-pc-windows-msvc.zip.sha256"
    }
  }
}
```

| Field | Meaning |
| --- | --- |
| `version`, `tag`, `source` | Exactly which upstream release the files came from |
| `assets.<id>.upstream` | Upstream file that was downloaded (useful with `pattern`) |
| `destination` | Repository-relative path of the committed file |
| `size`, `sha256` | Of the committed file |
| `verifiedBy` | `sha256:<checksum file>`, `sha512:<checksum file>`, `provider-digest` or `none` |

## Why it exists

- **Review:** MR diffs show the upstream file and hash, not just "binary changed".
- **Integrity:** `toolbot verify` re-hashes committed files on every pipeline.
- **Consistency:** a version bump without matching artifacts, or a hand-edited binary, fails CI.

The file is deterministic, with no timestamps and sorted assets, so re-running an update for the same version produces no diff.
